# API версии 1.2

Базовый путь — `/api`. Исключения: `/media/:id/:width`, `/health/live`, `/health/ready`. Полный маршрутный контракт с JSON DTO находится в `contract.md`; ниже — правила использования фактической реализации.

## Сессия и права

Каталог, категории, карточки и публичные настройки читаются без телефона и входа. `POST /auth/telegram {initData}` проверяет HMAC, свежесть, дубли и канонический replay-digest. В ответ устанавливается HttpOnly cookie. `GET /auth/me` возвращает `{user:null,dev:false}` либо текущего пользователя. Роль читается из БД при каждом запросе.

`/me`, `/checkout`, `/orders`, `/operations` требуют сессию; покупатель получает только свои объекты. `/staff` требует STAFF/OWNER, `/owner` — OWNER. В production изменение владельцем требует Origin, свежую авторизацию и заголовок `X-Owner-Code` с текущим TOTP. Токены не передаются в URL. `POST /auth/dev` существует только при явно локальном режиме вне production.

`POST /telegram/webhook` требует `X-Telegram-Bot-Api-Secret-Token`; update_id дедуплицируется. Контакт связывается только при совпадении отправителя и contact.user_id. Пароли/паспорт/карты не запрашиваются.

## Команды и повтор

Для команд остатков, броней, отмены, выдачи, отправки, возврата и редактора передавать `Idempotency-Key` длиной 8–120 символов из букв/цифр/`-_:`. Новый ключ нужен новому намерению; повтор того же тела с тем же ключом возвращает исходный результат. Иное тело или endpoint — 409 `IDEMPOTENCY_MISMATCH`. Записи результатов шифруются и проверяются по текущим правам.

После потери HTTP-ответа читать `GET /operations/:key`; если результат ещё неизвестен, повторять исходную команду с прежним ключом. До выяснения не начинать вторую фактическую выдачу. Для изменения существующего объекта передавать актуальный `version`; 409 требует чтения и повторного решения пользователя.

```http
POST /api/checkout/leases
Idempotency-Key: 9eb789dc-0d3c-4dd0-99b0-831def7da6f5
Content-Type: application/json

{"itemIds":["<UUID вещи>","<UUID вещи>"]}
```

Результат: `{id,expiresAt,items}`. Любой конфликт откатывает весь набор. Подтверждение:

```http
POST /api/orders
Idempotency-Key: 1a7d30c4-f6cc-42b2-8ff1-15dd1cd63199
Content-Type: application/json

{"leaseId":"<UUID удержания>","method":"PICKUP","phone":"<телефон>","termsAccepted":true}
```

Для BELPOST/EUROPOST добавить fullName, city, office и при необходимости postalCode/comment. Условия почты должны быть включены владельцем после проверки договора. Онлайн-оплаты нет.

## Дополнения к маршрутному контракту

| Метод / маршрут | Тело / результат |
|---|---|
| POST `/staff/items/bulk-hide` | `{items:[{id,version}],confirmed:true}`; все выбранные вещи доступны и без claims, либо весь набор 409 |
| POST `/staff/items/:id/inspect` | `{version,suitable:true,reason?}`; после физического осмотра, открытый ReturnCase блокирует публикацию |
| POST `/staff/items/:id/write-off` | `{version,reason}`; только владелец и после осмотра |
| PATCH `/staff/media/:id` | `{role?,position?,rotation?}`; положение — индекс с перестановкой всей последовательности |
| POST `/staff/issues/:id/assign` | `{}`; назначает текущего сотрудника и сохраняет аудит |
| POST `/owner/outbox/:id/retry` | Повтор после устранения причины; существующая заявка не дублируется |
| GET `/me/contact` | Серверный контактный черновик после разрешённого Telegram update |
| POST `/me/deletion-request` | Запрос очистки оперативных данных; активное исполнение/возврат сохраняет необходимое основание |
| GET `/owner/audit` | Фильтры actor/entity/from, before для страницы; без контактных данных |

Order DTO содержит независимые status/reservationStatus/shipment.status, построчные outcomes, точные даты, замороженные цены, proposal/cancelRequested и безопасные returnCases. ФИО/телефон, служебные заметки и оригиналы фото не публикуются. Для витрины используется available, а не клиентский счётчик количества. Фото публичной витрины — оптимизированные варианты; оригинал — защищённый маршрут сотрудника.

Ошибка: `{code,message,fieldErrors?,conflicts?,correlationId}`. 401 — сессия; 403 — права/Origin; 409 — версия/наличие/повтор; 410 — истёкший срок; 422 — поля; 429 — технический rate limit; 503 — БД/оформление недоступны. Время API — UTC, UI — Europe/Minsk; деньги — целые копейки BYN, замеры — миллиметры.

## Категории

`GET /categories` — активные категории из БД; `GET /staff/categories` — включая архив для служебных карточек; `GET /owner/categories` — управление владельца. `POST /owner/categories` принимает `name`, `measurements` (ключи стандартных замеров), `sortOrder`, `archived`. ID создаёт сервер. `PATCH /owner/categories/:id` также требует `version`; устаревшая версия возвращает 409. Изменения доступны только владельцу с production step-up, идемпотентны и записываются в аудит. Имена уникальны без учёта регистра русского/белорусского алфавита. Архивирование категории с вещами запрещено (409 CATEGORY_IN_USE); неизвестная или архивная категория отклоняется при сохранении вещи. Идентификаторы существующих категорий не меняются.


## Доработки по ТЗ от 02.11.2026

- Item API: `hasDefect:boolean` (по умолчанию false), `defectDescription:string` до 4000 символов. Включённый дефект с пустым/пробельным описанием — 422. Выключение очищает текст. Поля входят в published_snapshot, lease snapshot и order line snapshot; старые снимки без них остаются обычными вещами. Пометка не влияет на физический статус и QUALITY/INSPECTION.
- Settings: `about`, `phoneIsTest`, `documentStatus:DRAFT|APPROVED`. Изменённые документы сначала сохранить как DRAFT, затем отдельной командой утвердить. Реальные оформления требуют рабочего телефона, поддержки, реквизитов и утверждённых документов; production дополнительно проверяет это при удержании и подтверждении.
- Получатель/черновик: `officeAddress` до 500 символов, обязательный для новых заявок EUROPOST и изменений получателя EUROPOST; `office` — номер/название, `city` — населённый пункт. Для старых обращений читается прежний снимок без переписывания. BELPOST остаётся совместимым, индекс для EUROPOST необязателен.
- OWNER: миграция 007 и ADR-002. `/owner/*` mutations требуют свежего Telegram-входа и персонального второго фактора; код выдаёт пятиминутный grant только текущей сессии. Повтор кода в другой сессии запрещён. Нет публичного назначения OWNER/enrollment/reset. CLI отзывает сессии и пишет аудит.
- Уведомления: уникальность `(entity_id,entity_version,event_type,recipient_id)` сохранена. `SHIPMENT_REQUEST` остаётся совместимым; `OWNER_ORDER_REQUEST` — новая бронь самовывоза; `OWNER_ISSUE` — важная проблема, по одному каждому владельцу. Повтор одной открытой проблемы не создаёт повторов.
