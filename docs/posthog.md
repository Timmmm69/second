# Воронка «Лучка» в PostHog

По умолчанию выключена. Публичное демо, локальные тестовые роли и служебные экраны не отправляют события. Ничего не меняет в checkout, базе данных, Telegram-боте или отправках; SDK не подключается, поэтому нет автосбора, записи сессий, загрузки флагов и фоновых запросов к API магазина.

| Событие | Когда отправляется |
| --- | --- |
| `product_viewed` | Загрузилась карточка товара. Запросы предпросмотра ссылки не считаются. |
| `checkout_started` | Авторизованный покупатель открыл доступное оформление с товарами в корзине. |
| `order_submitted` | API вернул сохранённую заявку, в том числе при восстановлении результата. Не означает оплату, подтверждение менеджером или получение. |

Воронка измеряет визиты в одной вкладке: не более одного события каждого вида на вкладку, включая перезагрузки; случайный идентификатор живёт только в sessionStorage. После закрытия вкладки или при переходе из браузера в Telegram склейки визитов нет. События не пересылаются повторно после ошибки, поэтому возможен недосчёт; точное количество заявок и подтверждений берите из базы магазина, не из PostHog. Возможно оформление без просмотра отдельной карточки: полезно иметь основную воронку `checkout_started → order_submitted` и отдельную `product_viewed → checkout_started → order_submitted`.

В разбивке используйте `channel` (browser / telegram) и заранее известные метки `utm_source`, `utm_medium`, `utm_campaign`. Принимаются только точные комбинации из кода:

- `telegram / social / minsk_mir`
- `telegram / social / new_arrivals`
- `instagram / social / profile`
- `offline / qr / shop`

Метки работают, если параметры находятся в query страницы (перед `#`); произвольный текст, дублированные значения и необработанные параметры не отправляются. Telegram `startapp` здесь не используется для атрибуции.

## Проверка перед подключением

1. Выберите отдельный тестовый проект и проверьте бесплатный лимит и отсутствие платного превышения. Включите в настройках проекта **Discard client IP data**, проверьте, что отключены запись сессий и автосбор, и согласуйте применимые требования к уведомлению/согласию покупателей до запуска. Используется прямое браузерное соединение: PostHog получает сетевой IP на границе, даже если проект настроен не сохранять его. Профили и GeoIP запрещены на уровне события. Приложение не отправляет URL, referrer, Telegram ID или initData, адрес, поля формы, текст поиска или идентификатор заказа.
2. Укажите `POSTHOG_ANALYTICS_ENABLED=true`, `POSTHOG_PROJECT_TOKEN` (публичный ключ приёма событий, не персональный API-ключ) и `POSTHOG_REGION=eu` либо `us` в конфигурации **тестовой** среды. Переменные читаются API при старте; сборка интерфейса не меняется. Некорректный ключ, регион или отсутствие явного включения оставляют аналитику выключенной. Для отключения верните `false` и перезапустите API.
3. До реального сбора проверьте браузер и Telegram Mini App на тестовых данных: три ожидаемых события, отсутствие дублей после перезагрузки и восстановления заявки, ноль событий на предпросмотр ссылки или ошибку сохранения, отсутствие контактных данных и полный checkout при заблокированном запросе аналитики. Проверьте исключение служебных ролей и глобального сигнала браузера GPC/DNT.
4. В PostHog создайте Insights → Funnel с шагами из таблицы, порядком «в указанной последовательности» (промежуточные события допустимы), коротким окном конверсии (например, 30 минут), и разбивкой по `channel`. Сверьте несколько тестовых событий в Live Events. Подтверждение менеджером имеет смысл добавить отдельно только из подтверждённого серверного перехода и после согласования способа сопоставления.

Документация: [приём событий](https://posthog.com/tutorials/api-capture-events), [хранение IP](https://posthog.com/docs/privacy/data-storage), [тарифы](https://posthog.com/pricing).
