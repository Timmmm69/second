## Как повторить

Создать отдельную `veshi_test`, затем выполнить команды README. Suite намеренно не принимает рабочую БД. Тест с перезапуском включается отдельно:

```bash
RUN_DB_RESTART_TEST=1 \
PG_TEST_CTL=/полный/путь/к/pg_ctl \
PG_TEST_DATA=/путь/к/выделенному/тестовому/кластеру \
PG_TEST_SERVER_OPTIONS='-p 55432 -h 127.0.0.1' \
DATABASE_URL=postgresql://тестовый_пользователь@127.0.0.1:55432/veshi_test \
npm test
```

Не указывать рабочий или общий кластер: этот opt-in тест действительно останавливает и запускает PostgreSQL. Без opt-in обычный suite выполняет остальные 59 тестов и явно пропускает только перезапуск. Пересоздание отсутствующего диска/данных не моделируется как восстановление: резервных копий нет.

15 px занимает полоса прокрутки браузерного окна. В реальном мобильном WebView геометрия полосы и safe area отличаются.

Пройдено: вход локальной тестовой роли → две вещи → подборка → обязательный ручной телефон → удержание → бесплатная бронь №1001 → очередь владельца → построчная проверка → готовность до 3 ноября 20:00 → покупательская история и подробности. Две вещи исчезли из доступного каталога. Цена доступной сумки изменена сотрудником с 69 на 70 BYN, сервер сохранил новую версию, покупательская карточка показала новую цену. Просмотрены галерея, замеры, редактор и настройки владельца.

Исправлены блокирующая загрузка SDK, crypto.randomUUID на HTTP-preview, нестабильный фокус модального листа, повторяющиеся ID полей, маленькие сенсорные цели, цена Br вместо BYN, незаметная потеря выбранных строк массового снятия и несколько серверных конфликтов. Не выполнены исчерпывающие клики всех ошибок/переходов, реальное отключение сети телефона, камера/HEIC на устройстве, native requestContact/BackButton, iOS/Android и производственные кабинет/трек/посылка. Эти границы нельзя заменить количеством unit-тестов.

## Telegram iOS и Android — точные шаги

**Статус: не проверено из-за отсутствия реальных устройств/подключённого тестового бота.** Выполнить отдельно на iOS и Android с явно согласованным участником после подготовки HTTPS.

1. Открыть Mini App через menu/profile и ссылку на вещь. Публичный просмотр не запрашивает телефон. Вложенный экран включает нативную «Назад», корень её скрывает.
2. Пройти карточка → галерея → замеры → назад: закрывается верхний слой, затем маршрут; нет бесконечной петли. Проверить свайп/zoom и доступные кнопки галереи.
3. Выбрать несколько вещей, начать самовывоз. Запросить Telegram-контакт, затем отдельно отклонить разрешение и ввести номер вручную. Номер не объявляется автоматически полученным из initData.
4. Открыть клавиатуру в каждом поле, проверить safe area, focused input/ошибку, CTA и скрытую/перестроенную навигацию. Закрыть клавиатуру, сменить ориентацию, увеличить системный текст.
5. Заполнить телефон/ФИО, увести WebView в фон и вернуться, выгрузить и открыть заново. Контактный черновик восстановлен с сервера; ПД нет в CloudStorage/localStorage.
6. Подождать истечения lease в фоне: отправка должна перепроверить наличие, сохранить форму и показать понятное сообщение. Изменить доступность SKU с другого устройства; окончательное оформление берёт истину из БД.
7. Подготовить бронь сотрудником: точная дата Минска, выдача только с кодом. Проверить code attempts, частичный отказ, восстановление результата после потери ответа.
8. Снять служебную роль с открытого второго устройства: следующая команда запрещена, покупательские данные доступны только собственные.
9. Проверить обе почтовые цепочки на согласованных тестовых вещах: трек, сдача, статус с источником, возврат. Не выполнять реальных почтовых/денежных действий без отдельной договорённости.
10. Отключить сеть: ввод сохранён, состояние сети понятно, скрытых команд резерва/продажи/выдачи нет. Вернуть сеть и восстановить неизвестный результат по тому же ключу.

## Эксплуатационные проверки перед публикацией

- Compose health и миграции на целевом диске; закрытые порты БД/служебные файлы; `APP_MODE=local` невозможен в production.
- Перезапуск API/worker и PostgreSQL на сохранённых томах, завершение незаконченных операций. Это не испытание восстановления копии.
- Нет тестовых SKU/пользователей в рабочей БД. Пустая новая рабочая БД закрывает оформление до настройки.
- Нет платёжных SDK/маршрутов, продления и бизнес-лимитов 5/2.
- Разбор outbox 429/403 и простоя worker в локальной среде; без реальных сообщений несогласованным людям.
- Контроль места и доступности БД. При потере диска оформление выключено, восстановление без копии не обещается.
